前言

状态空间搜索根据是否使用启发式信息（Heuristic information）分为无信息搜索（Uninformed Search）和有信息搜索（Uninformed Search）。在本文中，我们先对有信息搜索的算法进行学习和复现。常用的无信息搜索算法包括：贪婪最佳优先算法(Greedy Best First Search, GBFS)和A*算法等。在图搜索算法中，使用代价函数 $f(n)$ 来作为优先级判断的标准， $f(n)$ 越小，优先级越高，反之优先级越低。

贪心搜索（GS）

原理

BFS和DFS的区别主要在于节点的弹出策略，根据弹出策略的区别，分别使用了队列和栈两种数据结构，而栈和队列作为两种相当基本的容器，只将节点进入容器的顺序作为弹出节点的依据，并未考虑目标位置等因素，这就使搜索过程变得漫无目的，导致效率低下。

而贪心搜索也是图搜索算法的一种，其使用的数据结构与狄克特拉斯算法的相同，即优先队列(Priority Queue)。普通队列是一种先进先出的数据结构，而在优先队列中元素被赋予了优先级，最高优先级元素优先删除，也就是first in, largest out。

GBFS作为一种启发式搜索算法，使用启发评估函数 $h(n)$ 来作为代价函数，也就是

$$f(n)=h(n)$$

其中 $h(n)$ 是当前节点到终点的代价，它可以指引搜索算法往终点靠近，主要用**欧氏距离(Euclidean Distance)或者曼哈顿距离(Manhattan Distance)**来表示，它们的区别如下图：

假设有两个点 $(x1,y1)$ 和 $(x2,y2)$ ，则它们的欧氏距离和曼哈顿距离分别为：

$$\begin{aligned}&D_{Euclidean}=\sqrt{(x_1-x_2)^2+(y_1-y_2)^2}\&D_{Manhattan}=|x_1-x_2|+|y_1-y_2|\end{aligned}$$

实现

由上述原理，不难得到GBFS的伪代码：

算法名称：贪婪最佳优先搜索（Greedy Best-First Search, GBFS）
输入：图 G = (V, E)，起始节点 start，目标节点 target，启发式函数 h (n)
输出：从 start 到 target 的路径（如果存在），否则返回空列表

procedure GBFS(G, start, target, h):
    priority_queue ← 空优先队列
    visited ← 空集合
    parent ← 空字典

    priority_queue.enqueue((start, h(start)))
    parent[start] = null

    while priority_queue 非空:
        (current, _) ← priority_queue.dequeue()

        if current == target:
            return reconstruct_path(parent, target)

        if current in visited:
            continue

        visited.add(current)

        for each neighbor in G.adjacent_nodes(current):
            if neighbor not in visited:
                priority_queue.enqueue((neighbor, h(neighbor)))
                parent[neighbor] = current

    return 空列表

function reconstruct_path(parent, target):
    path ← 空列表
    current ← target
    while current ≠ null:
        path.insert(0, current)
        current ← parent[current]
    return path

算法特性

在最坏情况下，GBFS 需要遍历图中的所有节点，因此时间复杂度为 $(O(V + E))$，在实际应用中，由于启发式信息的引导，算法通常能够在较短的时间内找到目标节点。另外，GBFS 需要使用优先队列来存储待扩展的节点，因此空间复杂度主要取决于优先队列的大小。不难看出，贪心搜索算法在搜索速度和指向性方面具有一定的优势，但在保证最优解和处理复杂地图方面存在明显的不足。因此，其具有以下优缺点：

  • 优点

    1. GBFS算法能够迅速地朝着目标节点前进，减少了不必要的搜索，从而显著提高了搜索效率
    2. 启发式函数的使用赋予了算法明确的搜索方向，避免了像无信息搜索算法那样盲目地扩展节点

  • 缺点

    1. GBFS 只考虑当前节点到目标节点的局部代价，而不考虑从起始节点到当前节点的路径代价，使得算法容易陷入局部最优解，而无法找到全局最优路径
    2. GBFS 的性能高度依赖于启发式函数的选择，不同的启发式函数可能会导致不同的搜索效果，甚至可能使算法陷入无效的搜索

A*搜索

原理

对比GBFS和Dijkstra算法，两者都采用优先队列作为openlist，而代价函数的不同导致两者具有不同的优点：GBFS用节点到目标点的距离作为代价函数，将搜索方向引向目标点，搜索效率高；而Dijkstra算法采用起点到当前扩展节点的移动代价作为代价函数，能够确保路径最优。

那么可不可以将两者的代价函数进行融合，从而在保证路径最优的同时提高搜索效率？答案是肯定的，融合后的算法就是A*算法。

A*算法也是一种启发式算法，它的代价函数表示为：

$$f(n)=g(n)+h(n)$$

其中 $g(n)$ 为起点到当前扩展节点的移动代价函数， $h(n)$ 是启发函数，用节点到目标点的距离函数来表示。

根据这个式子，可以得到A*算法的几个特点：

  • 如果令 h(n)=0 ，A*算法就退化为Dijkstra算法；如果令 g(n)=0*，*A*算法就退化为GBFS算法。
  • 能否找到最优路径的关键是启发函数 h(n) 的选取，如果 h(n) 在大部分情况下比从当前节点到目标点的移动代价小，则能找到最优路径。

实现

由上述原理，不难得到A*算法的伪代码：

算法名称：A* 搜索（A* Search）
输入：图 G = (V, E)，起始节点 start，目标节点 target，边的代价函数 cost (u, v)，启发式函数 h (n)
输出：从 start 到 target 的最短路径（如果存在），否则返回空列表

procedure AStar(G, start, target, cost, h):
    priority_queue ← 空优先队列
    visited ← 空集合
    parent ← 空字典
    g_cost ← 空字典
    f_cost ← 空字典

    g_cost[start] = 0
    f_cost[start] = h(start)
    priority_queue.enqueue((start, f_cost[start]))
    parent[start] = null

    while priority_queue 非空:
        (current, _) ← priority_queue.dequeue()

        if current == target:
            return reconstruct_path(parent, target)

        if current in visited:
            continue

        visited.add(current)

        for each neighbor in G.adjacent_nodes(current):
            tentative_g_cost = g_cost[current] + cost(current, neighbor)

            if neighbor not in visited or tentative_g_cost < g_cost[neighbor]:
                g_cost[neighbor] = tentative_g_cost
                f_cost[neighbor] = tentative_g_cost + h(neighbor)
                parent[neighbor] = current
                priority_queue.enqueue((neighbor, f_cost[neighbor]))

    return 空列表

function reconstruct_path(parent, target):
    path ← 空列表
    current ← target
    while current ≠ null:
        path.insert(0, current)
        current ← parent[current]
    return path

算法特性

A * 算法依赖优先队列来存储待扩展的节点。优先队列中的节点依据估计总代价$f(n)$排序，$f(n) = g(n) + h(n)$，其中$g(n)$是从起始节点到当前节点$n$的实际代价，$h(n)$是从当前节点$n$到目标节点的估计代价。这种数据结构使得算法能优先扩展那些看起来最有希望通向目标的节点，加速搜索进程。A * 算法的时间复杂度理论上为$(O(b^d))$，其中$b$是分支因子（每个节点平均的子节点数），$d$是解的深度。实际中，由于启发函数的作用，其时间复杂度往往远低于该理论值。而其空间复杂度主要取决于优先队列的大小。因此，其具有以下优缺点：

  • 优点

    1. 在满足启发函数$h(n)$满足一定条件时，A*算法能保证找到从起始节点到目标节点的最短路径
    2. 与无信息搜索算法（如 BFS、DFS）相比，A*算法可以避免遍历大量不必要的节点，减少搜索空间，从而显著提高搜索效率

  • 缺点

    1. 启发函数的质量直接影响 A * 算法的性能，若启发函数估计不准确，可能导致算法效率降低
    2. 内存消耗大且计算开销大

应用

数字华容道问题中，华容道的每个状态就是一个节点，我们的目标就是要从初始节点出发最快到达目标节点。这个问题和图搜索是非常类似的。因此，我们可以尝试使用A*算法来解决如图这道8数码华容道问题。

对于数字华容道问题而言，其移动代价函数$g(n)$即为从初始状态出发到达目前这个状态的步数，而其启发函数$h(n)$衡量的是当前状态距离目标状态的距离，该函数可以有多种不同定义，最常见的有两种：①不在正确位置的数字块的个数 ②每个数字块距离自己正确位置的距离之和。因为每个方块只能上下左右运动，因此这里第二种定义采用的是曼哈顿距离。接下来，我们分别对比这两种启发函数的定义解决该问题的效果。

采用不在正确位置的数字块的个数作为启发函数

采用每个数字块距离自己正确位置的曼哈顿距离之和作为启发函数

从结果上来看，两种定义都可以获得最终结果，且运行的步数都是26步。但采用曼哈顿距离之和的方法，在实际运行中只运行了2000~3000步，优先队列中存放的状态数量只有不到2000个，而采用第一种方法，则需要运行40000多步，且优先队列中存放的状态数量接近20000个。因此，采用曼哈顿距离之和的方法有更明显的趋向性，能使算法得到更高的运行效率。

虽然能够得到最终目标状态，但不难发现A* 实现中，有许多的缺点难以避免：在维护过程中需要记录所有搜索到的状态，需要大量的空间存储状态进行判重，也需要一些时间进行排序。因此我们考虑引入 IDDFS，即迭代加深。迭代加深之前介绍过，不了解的可以看这里。迭代加深是一种限制步数的深搜方式，它具备深搜的特点，但是每次只搜索深度限制范围内的所有点，再加上我们的估价函数进行剪枝，IDA* 就可以实现了。相较于 A*，IDA*具有 效率高、空间消耗小的优点。

最终只迭代了接近265万次就解决了该问题，且能够找到比单纯的A*算法更快速的操作方式。

总结

算法名称 原理 应用效果 算法特性
贪婪最佳优先搜索（GBFS） 使用优先队列，以启发评估函数 (h(n)) 作为代价函数 (f(n))，即 (f(n)=h(n))，(h(n)) 通常用欧氏距离或曼哈顿距离表示，指引搜索往终点靠近 - 指向性明显，从起点直扑终点
- 容易陷入局部最优陷阱，找不到最优路径		 - 优点：搜索效率高，能迅速朝着目标前进，减少不必要搜索；启发式函数赋予明确搜索方向
- 缺点：容易陷入局部最优解；性能高度依赖启发式函数选择
A * 搜索 融合 GBFS 和 Dijkstra 算法的代价函数，(f(n)=g(n)+h(n))，其中 (g(n)) 为起点到当前扩展节点的移动代价，(h(n)) 是启发函数 - 能成功避开局部最优陷阱
- 可以找到最优路径		 - 优点：能保证找到最短路径；与无信息搜索算法相比，可减少搜索空间，提高效率
- 缺点：性能受启发函数质量影响大；内存消耗和计算开销大
