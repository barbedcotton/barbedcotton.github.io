前言

状态空间搜索根据是否使用启发式信息（Heuristic information）分为无信息搜索（Uninformed Search）和有信息搜索（Uninformed Search）。在本文中，我们先对无信息搜索的算法进行学习和复现。常用的无信息搜索算法包括：深度优先搜索（Depth-First Search, DFS）、广度优先搜索（Breadth-First Search, BFS）、迭代加深搜索（Iterative Deepening Depth-First Search, IDDFS）和一致代价搜索（Uniform Cost Search, UCS）。众所周知，连通无回路图与树在本质上是等价的，它们可以相互转换，因此本文只以无环有向图为例来实现各种无信息搜索算法。

深度优先搜索（DFS）

原理

深度优先，顾名思义即深度较大的节点会被优先遍历。在DFS中，使用栈（Stack）数据结构来实现上述特性。栈是一种先入后出（LIFO）的容器，如下图：

实现

根据上述原理，很容易得到深度优先搜索的伪代码：

算法：深度优先搜索（DFS）
输入：图 G = (V, E)，起始节点 start，目标节点 target
输出：从 start 到 target 的路径（如果存在），否则返回空列表

procedure DFS(G, start, target):
    初始化：
        stack ← 空栈                 // 使用栈记录待探索节点
        visited ← 空集合             // 记录已访问节点
        parent ← 空字典              // 记录节点的父节点用于回溯路径

        stack.push(start)           // 将起始节点压入栈
        visited.add(start)          // 标记起始节点已访问
        parent[start] ← null        // 起始节点没有父节点

    while stack 非空:
        current ← stack.pop()       // 弹出栈顶节点
        
        if current == target:       // 找到目标节点
            返回 reconstruct_path(parent, target)  // 回溯路径
            
        for each neighbor in G.adjacent_nodes(current):  // 遍历相邻节点
            if neighbor 未在 visited 中:
                visited.add(neighbor)
                parent[neighbor] ← current
                stack.push(neighbor)  // 将未访问的邻居压入栈

    返回 空列表                      // 未找到路径

// 辅助函数：通过父节点字典回溯路径
function reconstruct_path(parent, target):
    path ← 空列表
    current ← target
    
    while current ≠ null:
        path.insert(0, current)     // 在头部插入节点
        current ← parent[current]   // 回溯到父节点
    
    返回 path

算法特性

因DFS需要借助递归工作栈的特性，其节点访问顺序取决于压栈顺序，若需要特定顺序（如字母序），可对邻接节点进行排序。在时空复杂度方面，在本次使用邻接表来表示图的情况下，时间复杂度为O(V+E)（V为顶点数，E为边数），空间复杂度为O(V)（最坏情况存储所有节点）。在路径回溯时，通过父节点字典反向追踪路径，并使用头部插入保持路径顺序，实现路径的正常输出。综上所述，其具有以下优缺点：

  • 优点：

    1. 能迅速找到一条可行路径，并能够记录所有可行路径
    2. 按照子树为单位进行搜索，需要较少的内存空间

  • 缺点：

    1. 要多次遍历，搜索所有可能路径，不能直接找到最优路径
    2. 在深度很大的情况下效率不高，甚至陷入死循环

原理

实现

根据上述原理，很容易得到广度优先搜索的伪代码：

算法：广度优先搜索（BFS）
输入：图 G = (V, E)，起始节点 start，目标节点 target
输出：从 start 到 target 的路径（如果存在），否则返回空列表

procedure BFS(G, start, target):  
    初始化：  
        queue ← 空队列                // 使用队列记录待探索节点  
        visited ← 空集合             // 记录已访问节点  
        parent ← 空字典              // 记录节点的父节点用于回溯路径  

        queue.enqueue(start)         // 将起始节点加入队列  
        visited.add(start)  
        parent[start] ← null  

    while queue 非空:  
        current ← queue.dequeue()    // 取出队列头部节点  

        if current == target:        // 找到目标节点  
            返回 reconstruct_path(parent, target)  

        for each neighbor in G.adjacent_nodes(current):  // 遍历相邻节点  
            if neighbor 未在 visited 中:  
                visited.add(neighbor)  
                parent[neighbor] ← current  
                queue.enqueue(neighbor)  // 将未访问的邻居加入队列尾部  

    返回 空列表                      // 未找到路径  

// 辅助函数：通过父节点字典回溯路径（与DFS相同）  
function reconstruct_path(parent, target):  
    path ← 空列表  
    current ← target  

    while current ≠ null:  
        path.insert(0, current)      // 在头部插入节点  
        current ← parent[current]  

    返回 path

算法特性

BFS 需要借助队列来工作，其节点访问顺序是按照先进先出（FIFO）的原则，从起始节点开始逐层向外扩展。若需要特定顺序（如字母序），同样可对邻接节点进行排序，使得在同一层中按照特定顺序访问节点。在时空复杂度方面，在本次使用邻接表来表示图的情况下，时间复杂度为O(V+E)（V 为顶点数，E 为边数，因为每个顶点和每条边都最多被访问一次），空间复杂度为O(V)（在最坏情况下，队列中可能存储图中所有的顶点）。在路径回溯时，通过父节点字典反向追踪路径，并使用头部插入保持路径顺序，实现路径的正常输出。综上所述，其具有以下优缺点：

  • 优点：

    1. 若存在最短路径（例如在无权图或边权相等的图中），BFS 能直接找到从起始节点到目标节点的最短路径。
    2. 由于是逐层搜索，在处理有环图时相对更稳健，不会因为深度过深而导致效率极低或陷入死循环

  • 缺点：

    1. 因为需要维护队列来存储待访问的节点，因此在图的规模较大时，具有较大的空间复杂度
    2. 对于某些问题，如果最优解在较深的层次，BFS 可能会遍历很多不必要的节点，导致搜索效率较低
